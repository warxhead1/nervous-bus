# kb lifecycle audit — 2026-08-30

Scope: is `~/knowledge/indexed` (5,762 entries, config at `~/.config/kb/config.yaml`)

## Headline

**The vault is accreting, not cycling.** Ingest keeps writing (5,372 → 5,762 entries,
+390/+7.3% in one day). The `log`-noise ratio held roughly flat (44.0% → 45.7%,
2,634/5,762) — not worse, but not improving either, because nothing downstream removes
or resolves entries. Every stage that should drain the vault (vet, review, gap-closure,
dedup) is either dead-on-arrival or actively erroring. One concrete, fixable bug
(`kb-autoingest.service` failing every ~30min cycle on a category-enum mismatch) is the
single highest-leverage fix available right now.

## Top 3 structural fixes, ranked by leverage (remediation ladder: eliminate > automate > inform)

1. **Eliminate the category-enum drift class** (stage 1, highest leverage). This is the *second* time in two days a canonical on-disk category has broken the wire validator (`audit` on 8/29, `shader-architecture` — 871 entries, the single biggest miss — today). Root cause is structural: the enum in `kb_entry_created_v2.rs` is a second source of truth for "what categories exist," maintained by hand, reactively, after something breaks. Fix: either (a) generate the enum from the same constant list every `kb` subcommand that writes `category:` frontmatter already imports, so it's impossible for a writer and the validator to diverge, or (b) make the v2 ingest event non-fatal on an unrecognized category (log + tag `category_unmapped: true` + continue) instead of hard-failing the whole systemd unit. Either change immediately fixes `kb-autoingest.service`'s every-cycle failure and directly resolves the `kb.autoingest.v1` 4.1d bus staleness (they are the same bug, not two).
2. **Automate the vet/evidence loop, or delete the landmark→vet contract.** 2,599 pending, net +907/week, ~0 draining outside the one automated shader-architecture pipeline, and `kb review list` shows the parallel propose/approve workflow has literally never been used. A CLAUDE.md/skill instruction telling agents to "call `kb landmark`" without a corresponding automated drain (bead-outcome → auto-vet, or a scheduled batch grader) manufactures an unwinnable backlog by design — this is the accretion mechanism, not a side effect of it. Either wire `kb watch`'s existing-but-underused bead-outcome→vet route as the default path for landmarks tagged with a bead ID (cheap, code already exists per `watch.rs:194`), or stop telling agents to land unvetted landmarks faster than any process can clear them.
3. **Make the enrich queue evict on permanent errors, and give the shader-architecture regen pipeline a supersede step.** Both are containable now (5 ENOENT retries per 8-item batch; 1,508 duplicate-titled files) but both compound identically to #1 and #2 if left alone — every regen cycle adds more slot_N copies with no archival, and every deleted vault file leaves a permanently-retrying enrich-queue ghost. Cheap, mechanical, no design risk.

## Steering paragraph — when a compaction-surviving session should reach for kb

Reach for `kb` only for what's *durable across sessions and unrelated to what git/repo docs already carry*, and route it correctly: `kb brief --project <p> "<topic>"` (never raw `kb query`) is the only sanctioned way to pull vault context into a dispatch prompt, because `brief` already deduplicates and demotes `category: log` noise that a raw query surfaces uncritically. Do not use `kb landmark` as a habit — the vault currently has 2,599 landmarked findings sitting unvetted with a median age of 26 days and effectively no automated or manual drain, so every landmark call today is a write into a queue that will not be read again; only land one when the finding is genuinely going to outlive this session AND you can immediately follow with `kb vet` (self-verified) or a bead that will trigger `kb watch`'s bead-outcome auto-vet. Never expect `kb query --embed`/`kb ingest --embed` to work unconditionally — they hard-depend on `hearth-api:8420`; prefer `kb context`/`kb find` which walk the vault locally and degrade gracefully. If a task needs cross-repo seam knowledge (HTTP routes, bus channels, process spawns), `kb codemap`/`kb relate`/`kb backlinks` are graph-native and cheaper than a text query. Treat the vault's `by category: log` bucket (45.7% of all entries) as near-zero-signal — it is auto-ingested session digests, not curated knowledge — and never cite it as evidence for a durable claim without opening the specific entry.
